# Mobius 프로젝트 보고서

## 1. 문제정의

- **개별 댓글 단위 모더레이션의 한계**: 기존 유해 댓글 탐지 도구는 게시물 하나하나의 유해성만 판정할 뿐, 특정 대상을 향해 계정·해시태그·반복 문구가 동시에 움직이며 공격이 확산되는 초기 국면(조직적 집단 공격의 발생·확산)을 포착하지 못한다.
- **피해자의 증거 수집 부담**: 신고·고소를 위해서는 피해자가 직접 게시물을 캡처·정리해야 하며, 삭제된 게시물은 증거를 잃는다. 무결성(수집 시점·원문 보존)을 입증할 수단도 없다.
- **텍스트 전용 탐지의 사각지대**: 조롱성 밈, 이미지 안에 삽입된 문구, 이미지+텍스트+해시태그 조합으로 발생하는 공격은 텍스트만 보는 도구로는 탐지되지 않는다.
- **판단 근거 부재로 인한 신뢰 문제**: 대부분의 유해성 탐지는 블랙박스 점수만 제공해, 피해자·기업이 "왜 위험하다고 판단했는지"를 확인할 수 없다.
- **트랙 분리 문제**: 피해자 개인 보호(실시간 알림·대응 가이드)와 기업/플랫폼의 위협 인텔리전스(대시보드·API)가 별도 시스템으로 존재해 하나의 신호를 양쪽에서 재사용하지 못한다.
- 참고 사례: 넥슨 '집게손가락' 사건 등 국내 실제 집단 공격 사례(공개 통계 기준 2개월간 3,500건 이상)가 문제의 실재성과 규모를 뒷받침한다.

## 2. 해결방안

### 2.1 서비스 컨셉
**Mobius**는 집단 온라인 공격의 확산 신호를 조기에 탐지하고, 설명 가능한 위험도·무결성 검증 가능한 증거 패키지·단계별 대응 가이드를 제공하는 웹 서비스다. 피해자 보호 트랙과 기업·플랫폼 B2B 트랙을 하나의 시스템으로 커버한다.

### 2.2 아키텍처 (수집 → 분석 → 개입 3단계 + 운영 계층)
```
[공식 API·고객 제공 데이터·허가된 공개 데이터]
        → Platform Connector (정규화·비식별화·중복제거)
        → Ingestion Layer (슬라이딩 윈도우 언급량 이상탐지 → 정밀분석 트리거)
        → 멀티스테이지 AI 분석 코어 (텍스트 분류 / 멀티모달 / 그래프-관계 / 시계열 Cascade 예측)
        → 설명가능 리스크 스코어링 엔진 (Pre-ignition → Ignition → Cascade → Aftermath)
        → 피해자 보호 트랙(대시보드·증거·알림) / B2B 트랙(위협 인텔리전스·API·알림)
        → 운영 계층 (인증/RBAC·로깅·MLOps·백테스트)
```

### 2.3 핵심 기능
| 영역 | 내용 |
| --- | --- |
| 텍스트 분석 | KLUE-RoBERTa 기반 이진 유해성 분류 + K-MHaS 기반 다중분류(욕설/혐오/조롱/협박 등 멀티라벨) |
| 멀티모달 분석 | 이미지 OCR로 밈 삽입 문구 추출 후 텍스트 분류에 합산, perceptual hash 기반 유사 이미지(재유포 밈) 탐지 |
| 그래프/관계 분석 | Neo4j 기반 계정·대상·해시태그 temporal graph, 클러스터·중심성·반복 문구·플랫폼 간 동시성으로 협조 행동 "의심 신호" 산출(확정 판정 아님) |
| 리스크 스코어링 | 언급 증가율·플랫폼 간 확산·유해성·협조 행동 신호를 정규화 후 가중합, 4단계 위험도와 근거·대응 가이드 자동 매핑 |
| 증거 자동 수집 | 게시글 원문·이미지·해시태그·타임스탬프 수집, SHA-256 해시로 무결성 검증 지원, PDF·JSON ZIP 패키지 원클릭 다운로드 |
| 피해자 트랙 | 실시간 대시보드, 위험 단계별 대응 체크리스트, 이메일 알림(쿨다운·묶음 처리) |
| B2B 트랙 | 위협 인텔리전스 대시보드, REST API(Swagger 문서화), 조직별 RBAC/멀티테넌트 |
| 운영 계층 | OAuth/JWT 인증, 원문/마스킹본 분리·보존기간(90일) 정책, 감사 로그, Docker 기반 배포 |

### 2.4 데이터 전략
- **학습/검증**: KOLD, BEEP(korean-hate-speech), K-MHaS 등 허가된 공개 데이터셋으로 텍스트 분류기 학습, 데이터 분할(train/val/test)로 벤치마크 성능 리포트화.
- **데모 시연**: 실제 스크래핑이 아닌 공개 통계 기반으로 재구성한 synthetic replay 데이터(`data/synthetic/`)를 사용하며, 보고서·발표에 시뮬레이션임을 명시.
- **거버넌스**: 공식 API·고객 제공·허가된 공개 데이터만 운영 데이터로 사용, 개인정보 마스킹·원문 분리 저장·최소 권한 접근·조직별 격리를 원칙으로 설계.

### 2.5 기술 스택
- **Web**: Next.js + TypeScript + Tailwind CSS (`apps/web`)
- **API/분석**: FastAPI + Python (`apps/api`)
- **비동기 워커**: `services/workers` (수집·분석·PDF 생성)
- **모델 학습/평가**: `services/ml` (train_text_classifier.py, train_multilabel_classifier.py, backtest.py)
- **데이터**: PostgreSQL(+pgvector), Neo4j(그래프), Redis
- **AI**: KLUE-RoBERTa / KcELECTRA 계열 트랜스포머, OCR
- **증거 문서화**: WeasyPrint/reportlab 기반 PDF 생성
- **운영/배포**: Docker Compose

## 3. 결론

### 3.1 개발 결과물
전체 구현 로드맵(`plan.md`) P0~P5가 모두 완료된 상태다.
- **P0**: 대시보드에서 멀티라벨 위험 근거·OCR/이미지 유사도·그래프·증거·알림 이력·역할별 화면을 웹만으로 전부 탐색 가능하도록 완성.
- **P1**: PostgreSQL에 조직/사용자/역할/대상/이벤트/증거/알림/감사 로그 테이블을 구축, 조직 간 데이터 접근을 404로 차단하는 멀티테넌트 격리 검증.
- **P2**: Google OAuth·JWT 세션, SMTP 알림(재시도·쿨다운·묶음 처리)을 키 유무에 따라 시뮬레이션/실제 동작으로 전환하도록 구현.
- **P3**: Neo4j 기반 temporal graph 증분 갱신, 협조 행동 점수(중심성·반복 문구·플랫폼 동시성), 이미지 perceptual hash 유사도 인덱스, 영상 확장 계약 시뮬레이션까지 완료.
- **P4**: 이진/멀티라벨 모델 평가 리포트, 시간 누수 없는 백테스트, E2E 테스트, 데모 시나리오·운영 문서화 완료.
- **P5**: 최신 Docker 이미지로 API·PostgreSQL·Redis·Neo4j를 통합 재기동해 전체 기능을 하나의 시나리오로 검증(`scripts/verify_p5.ps1`).

결과적으로 링크 하나(웹 대시보드)로 위험 근거, 공격 유형, 확산 그래프, 증거 패키지, 대응 가이드, 알림 이력을 모두 시연할 수 있는 상태다.

### 3.2 서비스 시나리오 (3분 데모, `DEMO_SCRIPT.md`)
1. **문제 제시(20초)** — 단일 게시물이 아닌 계정·해시태그·반복 문구의 동시 움직임이라는 초기 확산 신호를 포착함을 설명.
2. **로그인(20초)** — Google OAuth 또는 데모 세션으로 진입, 역할·조직은 자체 DB 초대/승인으로 결정.
3. **위험 근거(40초)** — 위험도, 유해성 모델 결과, 멀티라벨 공격 유형, 권장 조치를 대시보드에서 확인.
4. **그래프(40초)** — 계정·대상·해시태그 연결, 클러스터, 중심성, 동시성 점수 시연(협조 행동 점수는 검토 신호임을 고지).
5. **멀티모달·증거(30초)** — 이미지 OCR·유사 이미지 탐지, SHA-256 증거 ZIP 다운로드 시연.
6. **대응(20초)** — 이메일 경보, 쿨다운·묶음 정책, 조직별 이력 격리 설명.
7. **한계 고지(10초)** — synthetic demo·허가 데이터 범위, 오탐 가능성, 인간 검토 필요성 명시.

### 3.4 실험 결과 (`EVALUATION.md`)
데이터는 KOLD·BEEP·K-MHaS 등 허가된 공개 데이터와 synthetic replay 기준이며, 실제 피해·플랫폼 전체 성능을 주장하지 않는다.

| 모델 | 지표 | 결과 |
| --- | --- | ---: |
| 이진 유해성 분류 | Accuracy | 0.7810 |
| 이진 유해성 분류 | Precision | 0.7680 |
| 이진 유해성 분류 | Recall | 0.8193 |
| 이진 유해성 분류 | F1 | 0.7928 |
| 멀티라벨 공격 유형 | Micro F1 | 0.7852 |
| 멀티라벨 공격 유형 | Macro F1 | 0.6860 |

Macro F1이 Micro F1보다 낮아 희소 공격 유형에서 성능 편차가 남아 있으며, 탐지 결과는 확정 판정이 아닌 검토 우선순위 신호로 제시한다.

**조기경보 백테스트** (`data/synthetic/backtest_cases.jsonl`, 5분 단위 replay):

| Brier score | Precision | Recall | 리드타임 |
| ---: | ---: | ---: | ---: |
| 0.1641 | 0.6667 | 1.0000 | 5분 |

### 3.5 모델 실험 방법 및 결론
- **데이터 분할 원칙**: 이진 분류는 KOLD·BEEP·K-MHaS에서 train/val/test를 분리해 학습·검증·시험. 멀티라벨 분류는 K-MHaS의 다중 혐오 라벨을 사용.
- **시간 누수 차단**: 시간 기반 백테스트는 synthetic replay를 시간순으로만 처리하고, 경보 시점 이후 레코드는 이전 예측에 사용하지 않도록 설계해 미래 데이터 유입을 차단.
- **재현 명령**: `python services/ml/backtest.py data/synthetic/backtest_cases.jsonl`
- **결론**: 이진 유해성 분류(F1 0.7928)와 멀티라벨 공격 유형 분류(Micro F1 0.7852)는 실사용 가능한 수준의 성능을 보였고, 조기경보 백테스트에서 Recall 1.0·5분 리드타임으로 위험 급증 이전에 경보가 가능함을 확인했다. 다만 Macro F1 편차, synthetic 데이터 기반 시연이라는 한계로 인해 자동 제재가 아닌 인적 검토를 전제로 한 "검토 우선순위 신호" 제공 도구로 자리매김한다.
- **한계 및 향후 과제** (`OPERATIONS.md`): 모델/OCR/Neo4j 장애 시 fallback 상태 반환, 협조 행동·유해성 점수는 인적 검토·이의제기 절차 필요, 영상 STT는 확장 계약만 구현되어 실제 처리 전 별도 동의·보존 정책이 요구됨.
