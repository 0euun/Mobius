# Mobius 개발 구성안 (AI Innovation Challenge)

목표: 수상. 코딩은 에이전트가 처리하므로 시간/난이도 제약 없이, 제안서에 언급된 기능을 빠짐없이 반영하고, 각 기능을 실제 서비스 수준으로 고도화한다.

---

## 1. 심사 관점에서의 승부처

제안서에서 짚은 차별화 포인트:

1. 개별 댓글 유해성이 아니라 **집단 공격의 발생/확산을 예측**한다는 것
2. **텍스트 + 이미지(밈) 멀티모달** 탐지
3. **증거 자동 수집** — 피해자가 직접 캡처할 필요 없음
4. **피해자 트랙 + B2B 트랙**을 하나의 시스템으로 커버

여기에 더해, 완성도를 실제 제품 수준으로 끌어올리기 위한 요소(설명가능성, 신뢰성 검증, 보안/개인정보보호, 운영 파이프라인)까지 갖추면 "아이디어는 좋은데 구현이 얕다"는 심사 코멘트를 원천 차단할 수 있다.

---

## 2. 데이터 전략

**(A) 모델 학습/검증용 — 실제 공개 데이터셋**
- KOLD, BEEP, K-MHaS로 텍스트 분류기 학습/검증
- 자체 라벨링 데이터 추가 구축: 은어·반어적 조롱·팬덤/게임 커뮤니티 용어 등 국내 맥락 반영
  - 유료 라벨링 SaaS 대신 규칙·용어사전·공개 데이터 기반 분류 모델·LLM 판정을 결합한 자체 약지도(auto-labeling) 파이프라인 구축
  - 규칙과 모델의 예측이 일치하거나 신뢰도가 높은 pseudo-label만 재학습 데이터로 채택. 불일치·저신뢰 사례만 LLM 판정 대상으로 분리
  - 휴먼 리뷰는 전체 라벨링이 아닌 불확실 사례와 라벨별 무작위 표본 감사로 최소화하고, 라벨 출처별 일치율·신뢰도 분포·표본 정확도를 리포트화
- 벤치마크 성능 수치를 발표에서 제시 (정확도/F1/혼동행렬까지 리포트화)

**(B) 데모 시연용 — 명시적으로 "시뮬레이션"이라고 밝히는 재구성 데이터**
- 넥슨 '집게손가락' 사건 등 공개 통계(2개월간 3,500건 이상 등) 기반, 가상 인물/계정으로 재구성한 synthetic replay
- 압축 타임스탬프 재생으로 실시간 스트리밍처럼 시연
- "실제 스크래핑이 아닌 공개 통계 기반 재구성 시뮬레이션"임을 보고서/발표에 명시

**(C) 데이터 거버넌스**
- 운영 데이터는 **플랫폼 공식 API, 고객사가 적법하게 제공한 데이터, 수집·이용이 허가된 공개 데이터**만 사용. API 접근이 제한된 플랫폼은 임의 스크래핑 대신 고객 데이터 업로드·웹훅·공식 제휴 연동 지원
- 수집 데이터 내 개인정보(전화번호, 주소, 주민번호 패턴 등) 자동 마스킹·비식별화 처리, 수집 최소화 원칙 적용
- 원문과 마스킹본을 분리 저장하고, 원문 접근은 최소 권한·감사 로그 기반으로 통제
- 데이터 보존 기간, 삭제 요청 처리 및 삭제 로그 정책 수립·문서화
- 데이터 편향성 점검: 특정 플랫폼·연령대·성별에 편중된 학습 데이터 여부를 주기적으로 검증
- 멀티테넌트 환경에서 조직별 데이터·암호화 키·권한을 논리적으로 격리

## 3. 시스템 아키텍처 (수집 → 분석 → 개입 3단계 + 운영 계층)

```
[공식 API · 고객 제공 데이터 · 허가된 공개 데이터]
                │
        [Platform Connector → 정규화·비식별화·중복제거]
                │
        [Ingestion Layer: Kafka + Flink/Spark Streaming]
                │  (5분 슬라이딩 윈도우 언급량/증가율 측정, 이상탐지 알고리즘으로 급증 감지 → 정밀분석 파이프라인 활성화)
                ▼
        ┌───────────────────────────────────────────────────┐
        │                멀티스테이지 AI 분석 코어                │
        │  텍스트 분류   멀티모달(이미지·영상)   그래프/관계   시계열 Cascade 예측  │
        └───────────────────────────────────────────────────┘
                │
        [설명가능 리스크 스코어링 엔진: Pre-ignition/Ignition/Cascade/Aftermath]
                │
        ┌───────────────────┴───────────────────┐
   [피해자 보호 트랙]                     [기업·플랫폼 B2B 트랙]
   실시간 대시보드 + 증거 자동수집/PDF        위협 인텔리전스 대시보드 + API + 알림 연동
                │                                       │
        └───────────────────┬───────────────────────────┘
                             ▼
              [운영 계층: 인증/권한관리 · 로깅/모니터링 · MLOps · 백테스트/검증]
```

## 4. 기능영역별 구성

### 4.1 데이터 수집 및 스트리밍
- 수집 경로: X, Instagram, YouTube, Threads, 국내 온라인 커뮤니티의 공식 API, 고객사가 제공한 적법한 데이터, 수집·이용이 허가된 공개 데이터
- 수집 대상: 게시글, 댓글, 멘션, 해시태그, 이미지, 링크, 영상(YouTube 프레임 단위 샘플링 포함)
- 저장 메타데이터: 작성 시간, 작성자 ID, 게시글 URL, 좋아요 수, 공유 수, 댓글 수, 원본-답글 관계
- Apache Kafka + Flink(또는 Spark Streaming) 기반 실시간 처리, 파티셔닝으로 플랫폼별 처리량 분리
- 5분 단위 슬라이딩 윈도우 + Z-score/EWMA 기반 이상탐지로 특정 대상 부정 언급 급증 판별 (단순 threshold보다 통계적으로 견고)
- 활성화 트리거 로직: 부정 게시글 급증 또는 동일 해시태그의 다수 플랫폼 동시 사용 감지 시 정밀 분석 파이프라인(4.2~4.5) 자동 기동
- Platform Connector: 플랫폼별 데이터를 공통 이벤트 스키마로 정규화. API 접근이 제한된 경우 고객 데이터 업로드·웹훅·공식 제휴 연동으로 대체하며, 임의 스크래핑은 수행하지 않음
- 수집 신뢰성 보강: 중복 게시물 제거(deduplication), 수집 실패 시 재시도/백오프 로직, 플랫폼 API 장애 감지 및 대체 수집 경로

### 4.2 텍스트 분석
- KcELECTRA, KLUE-RoBERTa 기반 다중분류: 욕설, 혐오표현, 조롱, 비하, 협박, 명예훼손, 허위사실유포, 신상공개시도, 성적모욕
- 문맥 기반 분류로 "단순 비판"과 "집단 공격성 발언" 구분
- Emotion-Adaptive Training으로 풍자·조롱·비꼼 등 간접 공격 패턴 탐지 정교화
- LLM(Claude/GPT) few-shot 분류와 파인튜닝 모델 앙상블 비교 실험
- 은어·초성체·신조어 대응을 위한 자체 용어 사전 구축 및 지속 업데이트 체계
- Active Learning 루프: 분류 신뢰도가 낮은 케이스를 휴먼 리뷰 큐에 자동 전달 → 재학습 데이터로 축적
- Confidence Calibration: 분류 확률을 신뢰 가능한 확신도로 보정 (모델이 애매한 케이스를 스스로 인지)

### 4.3 멀티모달(이미지·영상) 분석
- CLIP 기반 VLM 또는 멀티모달 LLM(Claude Vision/GPT-4V 등) 활용, 성능/속도 비교 후 앙상블
- 합성 사진, 캡처 이미지, 조롱성 밈, 특정 손동작·상징 이미지 탐지
- 밈 내부 삽입 텍스트 OCR 추출 후 텍스트 분석 파이프라인과 결합 (이미지 안의 문구까지 분석)
- 이미지-텍스트-해시태그 결합 스코어링: 개별 요소는 중립이어도 조합 시 위험도 상승
- 재유포 이미지 추적을 위한 이미지 임베딩 기반 유사도 검색(perceptual hashing/CLIP embedding) → 동일 밈이 여러 계정/플랫폼에서 재사용되는 패턴 탐지
- YouTube 등 영상 콘텐츠는 프레임 샘플링 + 자막/음성 텍스트 추출(STT) 후 동일 파이프라인 적용

### 4.4 사용자 관계·확산 구조 그래프 분석
- 사용자, 게시글, 해시태그, 링크, 커뮤니티, 시간 정보를 노드/엣지로 구성 (Neo4j 기반 그래프 DB)
- 탐지 대상: 공격 시작 지점, 확산에 영향을 준 주요 계정, 동일 문구 반복 계정 그룹, 봇/가짜 계정 의심 패턴, 여러 플랫폼에서 동일 공격을 확산시키는 클러스터
- 동일 문구·동시성·공유 관계는 조직성을 단정하는 근거가 아닌 **협조 행동 의심 신호**로 표시하고, 판단 근거와 추가 검토 필요 여부를 함께 제공
- Cinus et al.의 Cross-platform Coordinated 행동 감지 방법론을 응용해 조직적 공격과 자연 발생적 확산을 구분
- HA-GCEN, Multi-Modal Discussion Transformer 접근을 참고해 텍스트·이미지·관계 정보를 통합 처리
- 그래프 임베딩(Node2Vec/GraphSAGE)으로 계정 간 유사도를 벡터화 → 신규 계정의 조직적 공격 가담 가능성을 사전 스코어링
- 실시간 그래프 업데이트: 스트리밍 데이터가 들어올 때마다 그래프를 증분 갱신(temporal graph)하여 시간에 따른 구조 변화 추적
- 인터랙티브 시각화: 노드 클릭 시 해당 계정의 활동 이력, 연결된 커뮤니티, 공유한 해시태그를 드릴다운

### 4.5 시계열 확산(Cascade) 예측
- 피처: 시간대별 게시글 수, 부정 멘션 수, 공유 수, 해시태그 증가율, 참여 계정 수, 플랫폼 간 이동 여부
- Stance-Aware GNN 기반 접근을 참고해 향후 공격 규모와 확산 시점 예측
- 예측 신뢰구간 제공(단일 수치가 아닌 범위로 제시)하여 과신을 방지하고 설명력 확보
- 복수 모델(Prophet 계열 시계열 모델 + GNN 기반 모델) 앙상블 후 성능 비교
- 시계열 검증: 사건의 시간 순서를 보존하여 과거 사건으로 학습하고 이후 사건으로 검증/테스트. 동일 사건의 미래 데이터가 학습 데이터에 섞이지 않도록 시간 누수를 차단
- 예측 대상: 향후 30분·2시간 내 부정 언급량, Cascade 단계 진입 확률, 위험 단계 전환 시점
- 기준 모델 비교: 이동평균·EWMA/Z-score·Prophet를 기준선으로 두고 텍스트·확산 피처 모델 및 GNN 앙상블과 비교
- 평가 지표: AUROC, PR-AUC, F1, MAE/RMSE, Calibration/Brier score, 예측구간 커버리지 및 조기경보 리드타임(실제 위험 급증보다 얼마나 먼저 경보했는지)
- 백테스트: 재구성 데이터에 대해 실제 언급량, 기준 모델 경보, Mobius 경보를 하나의 타임라인으로 시각화하여 사후 검증
- 상태 전환 시점에만 LLM을 호출해 자연어 경고 문구 생성
  - 예: "최근 30분 동안 부정적 멘션이 평소 대비 8배 증가했습니다"
  - 예: "동일 해시태그가 3개 플랫폼에서 동시에 확산되고 있습니다"
  - 예: "향후 2시간 내 공격성 댓글이 급증할 가능성이 높습니다"

### 4.6 설명가능 리스크 스코어링 엔진
- 입력 지표(언급 증가율, 플랫폼 간 확산, 유해성 심각도, 협조 행동 의심 신호)를 0~1 범위로 정규화
- 라벨링된 과거 사례 데이터로 학습·보정한 가중치 기반 점수로 산출하고, 예측 신뢰구간을 함께 제공. 단일 요소가 0이라고 전체 위험도가 0이 되지 않도록 설계
- 4단계 구분: Pre-ignition → Ignition → Cascade → Aftermath
- 단계 전환에는 히스테리시스와 최소 유지 시간을 적용하여 경보 단계가 짧은 시간에 반복 전환되는 현상 방지
- 단계별 대응 가이드 자동 매핑: 계정 보호, 댓글 제한, 플랫폼 신고, 법적 대응 준비
- 가중치 고정값이 아닌, 라벨링된 과거 사례 데이터로 가중치를 학습/보정하는 옵션 추가 (곱셈 공식은 유지하되 계수 튜닝)
- SHAP 등 설명가능 AI 기법으로 "왜 이 점수가 나왔는지"를 4개 구성요소별 기여도로 분해해 제시 → 피해자/기업이 결과를 신뢰할 수 있는 근거 제공

### 4.7 피해자 보호 트랙 — 실시간 대시보드
- 표시 항목: 현재 위험 수준, 최근 언급량 변화, 주요 공격 키워드, 공격 발생 플랫폼, 유해성 점수 높은 게시글, 증거 수집 현황
- 위험 단계별 대응 가이드 노출
- 위험 단계 진입 시 이메일/문자/앱 푸시 알림 자동 발송
- 알림 빈도 제어와 묶음 알림을 제공해 과도한 경보로 인한 피해자 부담을 방지
- 각 판정에 사용된 근거를 표시하고, 사용자가 오탐 신고·검토 요청·알림 제외를 할 수 있도록 휴먼 리뷰 큐와 연결
- 대응 체크리스트 제공: 계정 비공개 전환, 댓글 제한 설정법, 플랫폼 신고 바로가기 링크, 법률 상담 연계처 안내
- 정신건강 지원 연계 정보 노출(전문기관 상담 링크) — 피해자 심리적 부담 경감

### 4.8 증거 자동 수집 & 패키징
- 저장 항목: 게시글 URL, 작성자 ID, 작성 시각, 원문, 댓글/답글 내용, 이미지 캡처, 해시태그, 플랫폼명, 수집 시각, 유해성 점수, 공격 유형
- 유형별 자동 분류: 명예훼손 의심, 신상공개 의심, 협박성, 성적 모욕성
- WeasyPrint/reportlab으로 신고·고소용 PDF 리포트 자동 생성, ZIP 압축 다운로드 원클릭 제공
- 수집 시점 해시값(SHA-256)과 타임스탬프를 기록하여 **무결성 검증을 지원하는 증거 패키지** 제공. 법적 증거능력은 사건·관할·수집 방식에 따라 별도 판단됨을 명시
- 해외 플랫폼 게시물 자동 번역 첨부(신고·고소 자료 제출 시 활용도 향상)

### 4.9 기업·플랫폼 B2B 트랙
- 위협 인텔리전스 대시보드: 공격 발생 플랫폼, 진앙 커뮤니티, 확산 경로, 주요 공격 계정 클러스터, 영향력 높은 확산 계정, 공격 키워드 변화, 신고 우선순위 게시물 시각화
- REST API 제공 항목: 특정 키워드의 현재 위험 점수, 부정적 언급 증가율, 공격성 게시물 목록, Coordinated Behavior 클러스터 여부, 확산 예측 결과, 증거 수집 결과, 신고 우선순위 정보 (Swagger 문서화)
- 이메일 연동으로 위험 단계 진입 시 담당자에게 자동 알림
- 조직별 권한 관리(RBAC)로 다수 기업·기관이 동일 시스템을 안전하게 공용 사용(multi-tenant)
- 정기 리포트 자동 생성(주간/월간 위협 동향 요약) 기능

### 4.10 운영 계층 (신뢰성·보안·지속개선)
- 인증/권한관리: API Key 및 OAuth 기반 접근 제어
- 개인정보 보호: 원문/마스킹본 분리, 최소 권한 접근 제어, 테넌트 격리, 보존기간·삭제 요청 처리 및 감사 로그 운영
- 로깅/모니터링: 각 파이프라인 단계별 처리 시간·에러율 추적, 장애 알림
- MLOps: 모델 버전 관리, 재학습 파이프라인 자동화, 신규 라벨 데이터 반영 주기 설정
- 시스템 부하 시 우선순위 큐잉(고위험 대상 우선 분석)으로 자원 효율화

## 5. 서비스 구현 방식 및 기술 스택

- 제공 형태: 피해자 트랙과 B2B 트랙을 하나의 **반응형 웹 서비스**로 구현하고, 역할 기반 권한에 따라 화면·기능을 분리. 심사 시 URL 하나로 대시보드, 그래프 탐색, 증거 패키지 생성 과정을 시연
- Web: Next.js + TypeScript + Tailwind CSS
- API/분석: FastAPI + Python
- 비동기·스트리밍: 초기에는 Redis + Celery/RQ, 고처리량 확장 시 Kafka + Flink
- 데이터: PostgreSQL + pgvector, 그래프 분석·시각화 고도화 시 Neo4j 병행
- 파일/증거: S3 호환 객체 스토리지(MinIO 등) + WeasyPrint
- AI: KLUE-RoBERTa/KcELECTRA, OCR, CLIP 임베딩. VLM·STT·GNN은 분석 코어 고도화 단계에서 추가
- 운영: Docker Compose, GitHub Actions, Sentry로 시작하고 규모 확대 시 Prometheus/Grafana·MLflow·Kubernetes로 확장

## 6. 발표/보고서에 넣을 문구 포인트

- "운영 데이터는 공식 API·고객 제공 데이터·허가된 공개 데이터만 사용하며, 시연은 공개 통계 기반 재구성 시뮬레이션으로 진행했다" → 윤리성·현실성 어필
- 텍스트 분류기 벤치마크 수치(KOLD/BEEP/K-MHaS 성능) + 앙상블 비교 실험 → 기술 신뢰도
- 멀티모달 데모(VLM/CLIP, OCR, 재유포 이미지 추적) → 텍스트만 보는 기존 모더레이션 도구와의 차별점을 실물로 증명
- 그래프 DB 기반 coordinated behavior 시각화 + 그래프 임베딩 → "개별 댓글이 아니라 집단 공격 구조를 본다"는 핵심 메시지를 시각적으로 뒷받침
- Stance-Aware GNN 기반 확산 예측 + 시간 누수 없는 백테스트·조기경보 리드타임 결과 → "사후 대응이 아닌 사전 예측"이라는 제안서 핵심 주장의 실증적 근거
- SHAP 기반 설명가능 스코어링 → "블랙박스가 아니라 신뢰할 수 있는 판단 근거를 제시하는 AI"라는 차별점
- "버튼 한 번으로 무결성 검증을 지원하는 증거 PDF 패키지 생성" → 피해자 실사용성 어필, 가장 임팩트 큰 데모 포인트
- 피해자 트랙 + B2B API/대시보드/알림 연동까지 완성 → 하나의 시스템이 두 트랙을 실제로 커버한다는 것을 증명
- 운영 계층(보안·MLOps)까지 설계 → 아이디어 수준이 아닌 실제 서비스화 가능한 완성도임을 강조
